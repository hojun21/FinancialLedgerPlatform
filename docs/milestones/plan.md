
### 1단계: 로그인과 당행이체 (미니 프로젝트)

- 당행이체: 출금과 입금을 하나의 트랜잭션으로, 원장에 차변·대변 기록
- 거래내역 조회
- 동시성 테스트, 멱등 키

**완료 기준:**
- 회원가입 → 계좌 개설 → 송금 → 상대방 거래내역 확인이 화면에서 동작
- 같은 계좌에 동시 출금 100건을 넣어도 잔고가 정확하고 절대 마이너스가 아님
- 전체 원장의 차변 합 = 대변 합
- 같은 멱등 키로 두 번 요청하면 한 번만 처리

## 7. 도메인 규칙 (코드를 제안할 때 항상 지키세요)

- **금액에 `double`, `float` 금지.** `BigDecimal` 또는 원 단위 `long`을 사용합니다.
- **복식부기:** 돈이 움직이면 항상 차변·대변 한 쌍을 원장에 기록합니다. 한 분개의 차변 합과 대변 합은 반드시 같습니다.
- **원장은 수정·삭제 금지.** 잘못된 거래는 반대 거래(정정 거래)로 바로잡습니다.
- **잔고는 절대 마이너스가 되면 안 됩니다.** 출금 전에 잔고를 확인하고, 확인과 차감은 같은 트랜잭션·같은 락 안에서 합니다.
- **락 순서:** 두 계좌를 함께 잠글 때는 항상 계좌 ID가 작은 쪽부터 잠급니다. (데드락 방지)
- **멱등성:** 이체 요청은 멱등 키를 받고, 같은 키의 요청은 한 번만 처리합니다.
- **여러 서버를 가정:** 자바 메모리 안의 락(`synchronized` 등)으로 정합성을 지키지 않습니다. DB 락이나 버전으로 지킵니다.
- **시간:** 모든 시각은 타임존을 포함해 저장합니다.

## 8. 용어 정리 (배우면서 계속 추가)

| 용어 | 뜻 |
|---|---|
| 원장 (Ledger) | 모든 돈의 이동을 기록한 장부 |
| 분개 (Journal Entry) | 한 번의 거래를 차변·대변으로 나눠 기록한 것 |
| 차변 / 대변 (Debit / Credit) | 분개의 왼쪽 / 오른쪽. 합이 항상 같아야 함 |
| 멱등성 (Idempotency) | 같은 요청을 여러 번 보내도 결과가 한 번 처리한 것과 같은 성질 |
| 대사 (Reconciliation) | 서로 다른 기록(원장, 잔고, 타행 내역)이 일치하는지 맞춰 보는 일 |
| 트랜잭션 (Transaction) | 모두 성공하거나 모두 취소되는 작업 묶음 |
